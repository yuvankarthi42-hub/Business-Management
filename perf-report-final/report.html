F. Cloudflare readiness

Yes for the everyday app — sign-in, billing, tables, kitchen, QR orders, items, stock, purchases, customers, payments, staff, reports, settings and the admin screens all run under 10 ms CPU per request on a large shop.

  • Before going live: apply the products.saveDesign fix (textile shops with big catalogues).
  • Exports (admin.exportCustomer, dataExport.mine): 0.7 s (normal) to 3.2 s (large) CPU — need Workers Paid or the Catalyst/Node server for those two routes.
  • Passwords: PBKDF2 at 20,000 iterations ≈ 4.3 ms per hash — sign-in ≈ 4.5 ms, fits. Keep PASSWORD_ITERATIONS at the default on the free plan.
  • QR menu rebuild on menus of ~2,000 items can take ~30 ms once per menu change; normal menus are well inside.
  • Free-plan limits not about CPU: 100,000 requests/day per account and 50 sub-requests per request — the busiest API here makes 96 database round trips (exports: ~436).
  • Numbers are from Node on this Mac; Workers CPUs are similar or a little slower — keep ~2× headroom in mind for APIs in “Watch”.

Method

  • The real backend (Express, same handlers) on fresh in-process SQLite databases — one per shop, like Turso. One request at a time, so each request's CPU is its own.
  • App CPU = process CPU for the request − time inside the SQLite engine (statements and migration scripts). That is the part a Cloudflare Worker pays for; on Turso the SQL runs remotely.
  • Scripted runs: every API, reads ×20, writes ×10, exports ×3, on a normal shop (300 items, 2,000 bills, 8 shops) and a large shop (2,000 items, 10,000 bills, 30 shops). Cold = first call after the server started.
  • Shop types: 30 sub-types × ~50 steps through the HTTP API, run twice on separate servers; pass/fail checked per step, with result checks on totals, GST defaults and reports.
  • Browser: the real web app (Vite, Catalyst mode) signed in as each shop's owner; every sidebar link and Support opened; console errors, script errors, error text and server 5xx recorded.
  • Automated tests: the backend suite on SQLite, Turso protocol (hrana) and in-memory stores, plus type checks of web and backend.
  • Not measured: real network latency to Turso, WhatsApp sending (not set up in test), file uploads to cloud storage.
